## 目的

关于一个国家国防态势的两个问题：它资助并维持多少军事能力，以及它在主要武器上依赖谁。前者来自世界银行的年度指标，后者来自 SIPRI 的武器转让登记册，归约为供应国份额。

由 `GET /api/military/v1/get-defense-industrial-base?country_code=<ISO2>` 与 MCP `get_defense_industrial_base` 提供。两者均需 Pro 订阅。

<Note>
此路由的查询参数是蛇形命名的 `country_code`，与本套件中使用 `countryCode` 的其他路由不同。参数名由 proto 的
`sebuf.http.query` 选项按路由固定，生成的服务端只读取该键。在此处发送 `countryCode` 不会被拒绝：处理程序会看到空的
国家代码，未通过 `^[A-Z]{2}$` 校验，并返回 HTTP 200 及 `available: false`——读起来像"该国无数据"，而不是一个错误请求。
</Note>

## 第一部分——军事能力

世界银行 `MS.MIL.*` 序列，每个国家每年一个观测值：

| 字段 | 序列 |
| --- | --- |
| `expenditurePctGdp` | 军费占 GDP 比重 |
| `expenditureUsd` | 以现价美元计的军费 |
| `personnel` | 武装部队人员 |
| `armsExportsTiv` | 武器出口，TIV |
| `armsImportsTiv` | 武器进口，TIV |

每项指标携带 `value`、`year`、`previousValue`、`previousYear`、`source` 及自身的 `available` 标志。前一次观测与当前观测一并提供，因此调用方无需第二次请求即可展示变化方向。各指标的年份不同——世界银行并不按同一时钟发布整个系列。

## 第二部分——供应国依赖

SIPRI 按年份发布供应国到接收国的转让数据。对每个进口国，种子程序在五年滚动窗口内计算：

- `suppliers`——每个供应国占该进口国 TIV 总量的份额
- `supplierHhi`——该依赖关系的集中度
- `windowStartYear` / `windowEndYear`——实际使用的窗口

```text
supplierHhi = sum(tivShare_i^2)   对每个供应国 i
```

此处以 0–1 报告，而非矿产所用的 0–10,000 标度。数值越高表示主导供应国越少。

### TIV 不是货币

趋势指标值衡量的是转让*量*——它是所交付军事能力的代理指标，依据已知的单位生产成本校准。它不是价格、不是合同金额，也不可与第一部分的美元军费数字相比较。切勿用货币符号呈现它。

### 映射覆盖率

`supplierHhi` 基于**完整**的正 TIV 分母计算。`suppliers` 仅列出供应方能解析为 ISO-2 国家的行。`supplierMappingCoverage` 是已映射的正 TIV 份额。

两者刻意不作调和：将未映射的 TIV 从分母中剔除会低估集中度，等于假装那些转让没有发生。在将所列供应国视为详尽名单之前请先读 `supplierMappingCoverage`——为 0.97 时名单基本完整；远低于此时，它只是一个样本。

### 保留

`supplierRetained: true` 表示该进口国此前已发布的记录在本轮未被刷新。种子程序会先带上每一条此前发布的进口国记录，再仅用本轮分片覆盖为新数据，因此保留通常是分片结转，进口国请求失败只是可能原因之一。此时 `supplierFetchedAt` 报告的是被保留记录的原始时间戳，而非本轮。被保留的记录是具有已知时效的真实数据，因此提供它而非空响应。

## 时钟

`fetchedAt` 是所提供数值中**最早**的来源时间戳，因此可安全地理解为"此处没有任何数据比它更旧"。其他部分可能更新。`industrialFetchedAt` 与 `supplierFetchedAt` 给出各部分的时钟。世界银行与 SIPRI 两部分按不同日程更新——SIPRI 的年度更新在每年三月发布。

## 许可

SIPRI 的条款要求署名并禁止再分发完整数据库。因此 WorldMonitor 存储并提供衍生的各国供应国份额，绝不提供贸易登记册本身。[数据源](/zh/data-sources)中的许可表记录了相关条款。
