_本方法论由 World Monitor 创始人 [Elie Habib](https://www.worldmonitor.app/blog/authors/elie-habib/) 维护。已发布的修订记录在[更正日志](/zh/corrections)中。_

[信任页面](https://www.worldmonitor.app/trust/)有一张月度表格，统计首次被标为**单一发布方**或**已佐证**的报道，在 24 小时和 7 天之后各带有什么标签。本页定义表中的每一个数字。

<Note>
**覆盖面，而非准确性。** 标签说明一则报道被多广泛地刊载，从不说明它是否属实。从单一发布方变为已佐证的报道，是后来被两个或更多发布方家族刊载，并不意味着它得到了证实。反方向变化的报道，是后来只被一个家族刊载，也不意味着它是错误的。
</Note>

## 定义

以下是第 1 版定义（API 中为 `definitionsVersion: 1`）。

| 术语 | 定义 |
|---|---|
| **标签** | 英文完整摘要给报道的覆盖标签：已佐证、单一发布方、仅第 4 层级来源，或证据不足。参见[新闻可信度评分](/zh/methodology/news-credibility)和[信任页面](https://www.worldmonitor.app/trust/)。 |
| **首次标签** | 报道在创建其报道记录的第一个摘要周期中所带的标签。如果一则报道的首次标签被记录了不止一次，以最早的一次为准，之后的记录按标签变化计算。只统计首次标签为单一发布方或已佐证的报道；首次标签为仅第 4 层级来源或证据不足的报道不在表中。 |
| **队列日** | 报道首次标签所在的 UTC 日期。每则报道只属于一个队列日。 |
| **检查点** | 首次标签时间加 24 小时，以及加 7 天。 |
| **检查点时的标签** | 摘要在检查点当时或之前为该报道记录的最后一个标签。已离开摘要的报道保留其最后一个标签。 |
| **标签相同** | 检查点时的标签与首次标签相同。在检查点之前改变又改回的报道计为相同。 |
| **标签改变** | 检查点时的标签是另一个被跟踪的标签。从单一发布方：被两个或更多发布方家族刊载。从已佐证：只被一个家族刊载。 |
| **其他标签** | 检查点时的标签为仅第 4 层级来源或证据不足。 |
| **n** | 该月已统计队列日中带有该首次标签的报道数。每一行都满足：相同 + 改变 + 其他 = n。 |
| **低 n** | n 小于 30。该行显示计数（例如“12 中的 9”），不显示百分比，并标为“low n”。n = 0 的行显示短横线，同样标为“low n”。不隐藏、不合并、不外推任何数据。 |
| **月份** | 队列日所在的 UTC 自然月。表格覆盖当月及之前 12 个月。 |

百分比四舍五入为整数，因此一行的三个百分比相加可能不恰好等于 100，但计数始终相加一致。

### 事实核查机构发布了评级

此列**未测量**。WorldMonitor 只在有人于 [/verify](https://www.worldmonitor.app/verify) 核查某个说法时查询已发布的事实核查（参见[修订与更正日志](/zh/corrections)），这些查询与报道没有关联。要测量此列，需要对每个队列中的每则报道进行一次事实核查查询，这会消耗 Google Fact Check Tools API 的配额。在此事决定之前，该列显示“Not measured”并附上原因，而不是被省略。

如果日后开始测量，它将统计那些有 IFCN 认证事实核查机构对高度匹配的说法发布了评级的报道，无论评级内容如何。WorldMonitor 不会把评级映射到真/假的尺度上。

## 何时统计一个队列日

当一个队列日中的每则报道都已经过 7 天检查点时，才统计该日：即该日开始后 8 天，再加一小时的余量，以便正在进行的摘要写入完成。在此之前，该日的报道完全不在表中，因此一个月的数字会随着其队列日被统计而增长。每个月都会列出它统计了多少个队列日以及是哪些日期。

每个队列日的数字只计算一次，之后不再修改。报道在检查点之后的变化不会改变表格。

### 被排除的日期

摘要每天最多写入 60,000 条事件。如果某一天达到该上限，所有结果依赖于这一天的队列日都会被排除在表格之外，并且该月会说明排除了多少天。摘要什么都没有记录的日子（例如此表出现之前）没有记录，也不被统计。

## 可复现性

表格只根据已记录的标签历史计算。

1. **事件。** 英文完整摘要按事件的 UTC 日期，向列表 `trust:calibration-events:v1:<YYYY-MM-DD>` 每个事件追加一行：报道的首次标签为 `f|<storyId>|<state>|<epoch ms>`，此后每次标签变化为 `s|<storyId>|<state>|<epoch ms>`，其中 `<state>` 为 `single-publisher`、`corroborated` 或 `other`。列表保留 21 天。
2. **日记录。** `seed-label-calibration` 种子程序读取一个队列日的列表、它的前一天（这样被记录两次的报道只在较早的那天计一次）以及之后七天的列表，按时间顺序重放每则报道的事件，并把计数一次性写入 `trust:calibration-day:v1:<YYYY-MM-DD>`。日记录保留 400 天，从不覆盖。
3. **表格。** 种子程序每六小时把最近 13 个月的日记录汇总到 `trust:label-calibration:v1`，由 `GET /api/news/v1/list-label-changes` 以 `calibration` 字段提供。

在 21 天的窗口内，可以用公开的规则（`shared/label-calibration.js`）从事件列表重新计算日记录。此后，日记录本身就是已记录的历史。

## 统一适用

以上每条规则只读取标签、报道的身份哈希和时间。没有任何话题、人物、政党、媒体或国家会改变定义或阈值，队列中的每则报道权重相同。

## 局限

- **只关乎覆盖面。** 表格衡量标签如何变化，而不是报道是否属实。
- **只含英文摘要。** 不统计其他语言和变体。
- **离开摘要。** 从摘要中消失的报道保留其最后一个标签，因此“标签相同”包括之后再无人报道的报道。
- **重新出现的报道。** 报道记录在 7 天无覆盖后过期，之后再次出现的报道会作为新报道再次统计。
- **事件丢失。** 如果事件写入失败，标签变化会在下一个摘要周期重试，但丢失的首次标签不会重试：该报道会从其队列中缺失，这会降低 n，但不会改变任何结果。
