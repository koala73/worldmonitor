国家每日历史记录仪表板在采集时观测到的数据。
您可以比较同一国家不同日期的评分，并查看精选新闻标题。
档案从每日任务启用后开始积累，无法重建更早的新闻。

## 快照内容

每个 UTC 日期包含采集时间、可选的 CII 和韧性评分，以及最多五条新闻标题。
每项评分包含来源观测时间和计算公式标识。
新闻保留标题、来源、分类以及 HTTP 或 HTTPS 链接，不存储文章正文。
筛选依据是英文摘要标题中明确出现的国家名称，并非完整的事件统计。
有歧义的名称需要带有限定信息的别名，例如 `Republic of Georgia`、`Guinea Conakry` 或 `Congo Brazzaville`。这种保守筛选可能遗漏相关标题。
新闻筛选覆盖此前 24 小时。摘要不完整时，记录保留 `news_partial` 标记。

CII 仅覆盖其监测的国家。韧性使用已发布的排名缓存，包括主榜之外已评分的国家。
缺失的评分保持缺失，实际观测到的数值零仍为零。
韧性的观测时间是排名发布时间，而不是各项底层指标的观测日期。

## 比较限制

CII 越高，表示越不稳定；韧性越高，表示应对能力越强。
两者衡量不同概念，不应合并成一条风险趋势。

缺失日期、缺失评分或公式变化都会中断相应曲线。
响应通过 `ciiVersionBreak` 和 `resilienceVersionBreak` 标记这些情况。
请仅在公式标识相同的连续曲线内比较变化。
档案不会对缺失日期插值，也不会以零填补。

没有精选新闻标题不代表没有事件发生，只表示摘要筛选未为该国家和日期存储符合条件的标题。
档案为空也不代表该国家稳定。

## 读取历史

使用 `GET /api/intelligence/v1/get-country-history?country=US&days=30`。
`country` 参数为已分配的 ISO 两位字母国家代码。
时间范围包含 UTC 当天。`days=0` 或省略时默认为七天。

服务器根据已验证的调用者权限限制读取范围。

| 调用者 | 最大时间范围 |
| --- | --- |
| 匿名或免费用户 | 7 天 |
| Pro 或 Pro Business | 90 天 |
| API 或 Enterprise | 365 天 |

`requestedDays` 表示请求的范围，`effectiveDays` 表示权限限制后的范围。
`returnedDays` 为实际观测点数，可能小于 `effectiveDays`。
`allowedDays` 表示账户上限，即使档案为空也会返回。
响应使用 `Cache-Control: no-store`，防止较长历史通过共享缓存泄露。

MCP 工具 `get_country_history` 使用已认证调用者的身份读取同一个基于缓存的 API。
参数为 `country_code` 和 `days`，现有 MCP 订阅和配额规则仍适用。
若较长历史超出输出预算，工具会保留每天一条精选标题，并添加 `events_reduced_for_output_budget` 标记。

## 新鲜度与启用

在配置 Railway 服务后，任务每天约于 UTC 00:30 运行。
它读取现有 CII、韧性和新闻缓存，不调用评分构建器。
发布以原子方式替换当天记录，清除早于 365 个 UTC 日期保留范围的记录，并仅在确认发布后更新健康元数据。
较早的重叠任务无法覆盖较新的采集结果。

`upstreamUnavailable=true` 表示读取失败或档案尚未发布。
`stale=true` 表示档案不可用，或距上次成功发布已超过 36 小时。
健康端点在首次发布前报告待启用状态，并在启用后检测定时任务停止的情况。

不会自动回填历史。现有韧性历史采用不同的评分和时间定义，且不包含采集的新闻标题。
将其导入为完整的每日快照，会暗示档案曾做出实际并未发生的观测。
现有 CII 历史仍可通过原有工具访问。
