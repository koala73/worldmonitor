World Monitor Pro 可以在你选择的时间通过电子邮件发送全球风险摘要，默认时间为你所在时区的上午 8 点。摘要中的每条新闻都链接到它所来自的原始报道。同一份摘要也可以发送到 Telegram、Slack 和 Discord，每条新闻同样带有链接。

## 摘要包含什么

每份摘要涵盖自上一份摘要以来发布的排名靠前的新闻。第一份摘要涵盖过去 24 小时。

- **AI 执行摘要（可选）。** 根据你的关注列表和兴趣撰写的简短评估，概述这段时间的主要动态。电子邮件包含完整摘要，聊天渠道包含首段。可通过“AI 执行摘要”开关关闭。
- **按严重程度分组的新闻。** 依次为严重、高、中。严重部分不会被截短。高和中两部分显示排名靠前的新闻，并注明其余数量。
- **每条新闻。** 标题链接到原始报道，随后是报道该新闻的媒体，以及来自发布方订阅源的一行简介（如有）。
- **延伸链接。** 完整 World Monitor 简报就绪后附上其链接，并附上实时仪表盘链接。

新闻的筛选、排序和去重方式见[新闻摘要与简报方法论](/zh/methodology/news-digest-and-briefing)。

## 每条新闻都链接到原始报道

每个标题上的链接是来源订阅源中的文章网址。只使用 `http` 和 `https` 链接。没有可用文章网址的新闻会显示为不带链接的标题，而不是失效链接。

| 渠道 | 每条新闻的链接方式 |
| --- | --- |
| 电子邮件 | 标题是指向文章的链接。 |
| Telegram | 标题是指向文章的链接。链接预览已关闭，消息保持简洁。 |
| Slack | 标题是指向文章的链接。链接展开已关闭。 |
| Discord | 标题是指向文章的隐藏网址链接。嵌入预览已关闭。 |
| Webhook | JSON 负载包含每条新闻的标题、严重程度、阶段和媒体，但不包含文章网址。 |

聊天应用限制消息长度。较长的 Telegram 或 Discord 摘要会在达到上限前被截短，并尽量在行尾截断，避免把新闻链接截成两半。普通摘要的电子邮件没有这一限制。内容过大的电子邮件会删去优先级最低的新闻，并改为链接到完整简报。

## 发送频率

在网页版的 **设置 → 通知 → 发送模式** 中选择发送模式。

| 模式 | 发送时间 |
| --- | --- |
| 每日摘要 | 每天一次，在你选择的时间发送。 |
| 每日两次 | 在你选择的时间以及 12 小时后发送。设为上午 8 点时，晚上 8 点也会发送。 |
| 每周摘要 | 在你选择的时间发送，且距离上一份每周摘要至少已过六天半。 |
| 实时 | 事件发生时逐条发送提醒，而不是摘要。实时发送仅限严重事件。 |

发送时间按你在同一页面设置的时区计算。早间简报就是把发送时间设在早上的每日摘要。

**敏感度** 决定哪些新闻会被纳入：全部事件、高和严重，或仅严重。“全部事件”和“高和严重”只能与摘要频率搭配使用。

## 渠道

在 **设置 → 通知 → 渠道** 中连接渠道。摘要会发送到你已连接并完成验证的每个渠道。

- **电子邮件**：发送到你已验证的账户邮箱。
- **Telegram**：将 World Monitor 机器人连接到一个聊天。
- **Slack**：为某个频道添加传入 Webhook。
- **Discord**：添加频道 Webhook。
- **Webhook**：发送到你自己系统的已签名 JSON 负载。见[通知与集成](/zh/api-notifications)。

浏览器推送只接收实时提醒，不接收摘要。

## 使用要求

摘要和提醒规则需要付费套餐，见[价格](/zh/pricing)。通知设置位于网页版中，桌面应用不显示这些设置。

## 设置早间简报

1. 登录 [worldmonitor.app](https://www.worldmonitor.app)，打开 **设置 → 通知**。
2. 连接电子邮件或其他渠道。
3. 将 **发送模式** 设为 **每日摘要**。
4. 将 **发送时间** 设为你想要的早间时间，并设置你的 **时区**。
5. 选择 **敏感度**；如需书面评估，请保持 **AI 执行摘要** 开启。
