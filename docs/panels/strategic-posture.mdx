The **AI Strategic Posture** panel (internal id `strategic-posture`) surfaces theater-level military posture assessments. It shows the level the AIS relay published for each theater, the same level the API and the MCP tools report.

## What the panel shows

A vertical list of theater posture cards. Each card includes the theater name, the current posture summary, and click-through affordances: selecting a theater fires an optional location-click callback so the host can zoom the map to its coordinates.

The panel tracks elapsed time with a `setInterval` while waiting for the posture fetch to resolve, so the reader gets a visible progress signal on slow runs. When the seed is stale, the panel sets a stale indicator (`isStale`) so the card surface can flag it.

The panel loads posture via `fetchCachedTheaterPosture()` and renders it as published. It does not recompute levels. When a theater's target nation has an instability score of 70 or more, the card shows that score as a separate chip; the score does not change the level.

Panel id is `strategic-posture`; canonical component is `src/components/StrategicPosturePanel.ts`. Title resolves from i18n (`panels.strategicPosture`); config sets `'AI Strategic Posture'` at `src/config/panels.ts:23`.

## How you reach it

- **Cmd+K**: type *posture* or *strategic*.
- **Availability by variant**: registered and enabled by default in the **full/geopolitical** variant only. Free on the web; on desktop the variant registration spreads `{ premium: 'enhanced' as const }` into the config so the panel becomes enhanced-gated on the desktop build. Source: `'strategic-posture'` entry in `FULL_PANELS` at `src/config/panels.ts:23` (no `premium` set; desktop variants elsewhere layer on enhanced gating per the `_desktop &&` pattern).

## Data sources

- **Theater posture**: per-theater level, aircraft count and tracked-vessel count published by the AIS relay (`theater-posture:sebuf:v1`, rule in `scripts/shared/theater-posture.js`), read via `@/services/cached-theater-posture`.
- **Country instability**: cached CII scores via `@/services/cached-risk-scores`, shown as context only.

## Backed by endpoints

The panel does not call every military route directly. It reads bootstrap/cache posture data first, then uses the generated MilitaryService client only when the local posture cache needs a fresh server value.

| Method | Route | What it feeds |
|--------|-------|---------------|
| `GET` | `/api/military/v1/get-theater-posture` | Primary posture RPC for the card list. The browser checks bootstrap `theaterPosture`, circuit-breaker cache, and IndexedDB before falling through to this route. |
| `GET` | `/api/military/v1/list-military-flights` | Source feed for aircraft-driven posture and surge calculations upstream of the cached posture payload; the panel normally consumes the computed posture output rather than refetching flights itself. |

## Refresh cadence

The panel is not on a polling timer — it fetches on mount and re-renders on relevant external triggers. The AIS relay republishes theater posture every 10 minutes.

## Tier & gating

**Free on web; enhanced on desktop.** Registered without `premium` in the full-variant `FULL_PANELS` entry (`src/config/panels.ts:23`), so the web build doesn't gate it. The desktop build layers on `premium: 'enhanced'` in other variant contexts — this is why the panel appears free on web but behind an upgrade CTA on the desktop app.
