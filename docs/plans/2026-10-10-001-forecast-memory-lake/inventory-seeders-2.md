## How cadence was determined

1. `scripts/railway-services.json` `cronSchedule` (standalone Railway cron services).
2. Bundle membership: `scripts/seed-bundle-*.mjs` section `intervalMs` (the bundle cron ticks often; the section runs when its `intervalMs` has elapsed since `seed-meta`).
3. Script header comments, then `api/health.js` `SEED_META[*].maxStaleMin` comments (these state the intended cron). Where a service is not in `railway-services.json` (that file lists 56 services and is a partial snapshot), the cadence is labelled "(header/health)".

Credential column: `NAME (present)` / `NAME (absent)` in `.env.local` (names checked only). Railway env may differ from `.env.local`; absence locally does not prove the Railway service lacks it.

Every `runSeed(domain, resource, key, …)` call also writes `seed-meta:<domain>:<resource>` (TTL = max(7d, data TTL) via `writeFreshnessMetadata`), not repeated per row.

## Per-feed notes (grouped)

**Yield curves (rows 97–105).** All eight country seeders use `seed-yield-curves-shared.mjs`: canonical key = full daily history, plus `:latest` and per-year shards (`economic:yield-curve:{cc}:v1:{year}`), TTL 7d. The full history is re-fetched from the central bank each day, so the Redis copy is a cache of an upstream archive. GB is the exception: the daily zip only carries the current month, and the seeder merges into the previous canonical value (`seed-yield-curve-gb.mjs:47-64`). If the archive zip refresh fails at month rollover, history can gap. EU (`seed-yield-curve-eu.mjs`) keeps only the latest observation.

**World CPI (rows 93–96) and US macro (83–85).** Each payload holds a bounded or full upstream history (120 months / 40 quarters, or full FRED/Treasury history). The lake does not need to accumulate these; it needs vintages (revisions) if forecast evaluation must use as-of data. Nothing here stores vintages.

**IMF WEO family (9–12, 48).** WEO publishes forecasts for future years. Each run overwrites the vintage. The April/October WEO forecast vintages are lost unless archived.

**Resilience (20, 42, 47–52, 57, 58, 65).** Inputs are annual. `seed-resilience-scores.mjs` is derived (warm-pings the scorer and stores scores/ranking/intervals under `resilience:*:v29` / `v12`). Score history is not kept anywhere in this half; a version bump (`v29`) orphans prior scores.

**Market (2, 6, 22–24, 35, 43, 61, 62, 67, 74).** Quotes are snapshots. Accumulating series kept today: breadth (252 sessions), SGE premium history (750 points per metal, persistent), Hyperliquid sparklines (5 h). Prediction-market probabilities (row 43) are not retained, though they are the natural benchmark for forecast skill.

**Market-alert ledger (21).** Already a forecast-evaluation dataset: emissions in 6h windows, resolved against the digest archive under a pre-registered rule, no TTL on the ledger key. Its inputs (quotes snapshots, `digest:accumulator:v1:full:en`) are themselves short-lived.

**Conflict/security (15, 16, 26, 27, 59, 63, 81, 82).** UCDP keeps a trailing 365 days from an upstream archive (backfillable). ACLED path is dark (no credentials locally; memory notes ACLED dark in prod). Military flights write `military:forecast-inputs:v1` and request forecast refresh (`forecast:refresh-request:v1`). Surge history keeps 72 assessments, ≈6 h at the 5-minute cron. Sanctions keep only the previous ID set for diffing. Advisory levels are not historised.

**Regional intelligence (53, 54).** `seed-regional-snapshots.mjs` is the one feed in this half with a real time-indexed archive: per-region snapshots every 6 h, 90-day TTL, ZSET index pruned at 90 d, plus a persistent 100-entry regime-transition list. It is derived from about 15 input keys (listed in row 54). Briefs (53) are LLM output kept 15 d.

**Supply chain (4, 5, 38–41, 71, 72, 79).** PortWatch re-fetches 180 days of chokepoint transits and 60 days of port activity from ArcGIS, so these are backfillable. Hormuz tracker holds a 30-day chart window from a Power BI scrape (not backfillable from Redis). Shipping indices scraped from HTML (SCFI/CCFI/BDI) keep only the last 24 points, so they cannot be rebuilt from upstream APIs. Exposure and vulnerability (5, 72) are derived from Comtrade bilateral HS4 snapshots.

**Canada bundle (33, 44, 60, 75–80, 87).** Operational/local incident feeds at 5–30 min cadence, all snapshot-only, short TTLs. TPS open data (78) is on-demand and probably dark.

**Disabled / dormant / planned:** GTA Update (locked disabled), Iran events (sunset, flag-gated), weather-alerts / service-statuses / market-quotes standalone (Railway "planned"; relay owns those keys), TPS open data (on-demand), e-Stat JP CPI (needs ESTAT_APPID, absent locally), IMD (credentials absent locally), ACLED (absent).

Mineral production — IEA skipped for "redistribution terms". VIA Rail — unofficial, no SLA. Hormuz — public Power BI report. GTA Update — "reuse permission is held" but locked.
