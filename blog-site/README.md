## 🚀 Project Structure

Inside of your Astro project, you'll see the following folders and files:

```text
/
├── public/
├── src/
│   └── pages/
│       └── index.astro
└── package.json
```

Astro looks for `.astro` or `.md` files in the `src/pages/` directory. Each page is exposed as a route based on its file name.

There's nothing special about `src/components/`, but that's where we like to put any Astro/React/Vue/Svelte/Preact components.

Any static assets, like images, can be placed in the `public/` directory.

## 🧞 Commands

All commands are run from the root of the project, from a terminal:

| Command                   | Action                                           |
| :------------------------ | :----------------------------------------------- |
| `npm install`             | Installs dependencies                            |
| `npm run dev`             | Starts local dev server at `localhost:4321`      |
| `npm run build`           | Build your production site to `./dist/`          |
| `npm run preview`         | Preview your build locally, before deploying     |
| `npm run astro ...`       | Run CLI commands like `astro add`, `astro check` |
| `npm run astro -- --help` | Get help using the Astro CLI                     |

## Web fonts

The blog self-hosts subsets of Inter, JetBrains Mono and Space Grotesk. They are generated by hand and committed; the build does no font processing.

- `src/fonts/<family>-core.woff2`: ASCII, curly quotes, en and em dashes, the ellipsis, and any other character used on at least half of that family's pages. `Base.astro` preloads the three core files.
- `src/fonts/<family>-ext.woff2`: the rest of Latin-1 and Latin Extended-A, plus any other character the blog uses that Google Fonts drew in that family. Each file's `unicode-range` lists only the characters it contains, so the browser downloads an extended file only on pages that use one of them.
- `src/styles/fonts.generated.css`: the `@font-face` rules. `src/fonts/manifest.json` records what each file holds and why.

Characters Google Fonts never drew in these families (arrows such as ←, CJK, Arabic) are left out and keep rendering in system fonts.

### Regenerating

```sh
npm ci                          # once, in the repository root (Playwright)
npx playwright install chromium # once, the browser the crawl uses
cd blog-site
npm ci                          # once, the blog's build dependencies
npm run fonts:subset            # builds, crawls every page in Chromium, rewrites the files above
```

The script also needs [uv](https://docs.astral.sh/uv/), which installs its pinned Python dependencies. It downloads the pinned source fonts from google/fonts and checks them against SHA-256 hashes. Output is deterministic: rerunning with unchanged content reproduces the same bytes. Flags:

- `--skip-build` crawls the existing `dist/`.
- `--skip-google-parity` skips the comparison against Google's served files (for offline runs). Don't commit output produced this way.
- `uv run scripts/fonts/subset/subset_fonts.py --refresh-google-snapshot` rereads Google's CSS into `scripts/fonts/subset/google-fonts-snapshot.json`. Do this only when deliberately changing the reference rendering.

The script refuses to write files when a glyph outline or the shaping of any text run differs from Google's files at the weights the blog renders.

### When to rerun

`tests/blog-font-subsets-fresh.test.mjs` fails, and names the cause, when:

- content adds a character one of these fonts would draw but no subset contains (for example a Vietnamese or Polish letter outside Latin Extended-A);
- a font-related CSS declaration is added, removed, changed or moved to another rule (`font-weight`, `font-family`, `font-variant-*`, `font-feature-settings`, `font-variation-settings`, `text-transform`, `hyphens`, the `--font-*` stacks, and similar), including inline `style` attributes;
- a page uses a new `lang`;
- the committed files were generated with `--skip-google-parity`.

Also rerun after changing the font stack or the Google Fonts families in `subset_fonts.py`.
